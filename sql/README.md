## 교정한 조회→결제율

`archive/sql24.sql`은 모든 콘텐츠 행동 유저 중 결제자 수를 조회 유저 수로 나누었습니다. 두 집단이 달라 조회자의 결제 확률로 해석할 수 없습니다.
새 쿼리는 **같은 콘텐츠를 가입 후 7일 안에, 첫 결제 전에 조회한 유저**를 분모로 두고 그중 가입 후 30일 내 첫 결제자를 분자로 셉니다. 조회 로그 없이 시작한 유저는 이 조회자 지표의 분자·분모 모두에 들어가지 않습니다.
공통 `dm_user_activation_payment`의 유저 키 유일성과 `paid_30d` 정의를 전제로 합니다. 가입 후 관찰기간 완결성, 결제 이벤트 정의, 환불 처리는 별도로 확인해야 합니다.

## 보관 쿼리의 실행 범위

MySQL 계열의 `DATE_ADD`, `TIMESTAMPDIFF` 등을 사용합니다. `DROP TABLE`, `CREATE TABLE`, 추가 `INSERT`가 포함되므로 기록 전체를 기존 DB에 일괄 실행하지 마세요.

- `sql1`과 `sql2` 모두 가입 이벤트를 적재합니다. 순서대로 둘 다 실행하면 가입 이벤트가 중복될 수 있습니다.
- 로더 `sql2–12`는 반복 실행에 대한 중복 방지 장치가 없습니다. 원본 이벤트 키와 적재 이력을 확인해야 합니다.
- `Untitled.sql`은 `sql1.sql`과 유사한 작업 사본이며 세미콜론 누락이 있어 실행 진입점으로 사용하지 않습니다.
- `sql16`은 활성화·결제 마트 정의, `sql23`은 콘텐츠 성과 마트 정의입니다. 일반 7일 변수는 결제 후 행동도 포함합니다.
- 갱신 마트 생성 쿼리는 이 묶음에서 확인하지 못했습니다.

원시 DB가 제공되지 않아 이 저장소 정리 과정에서는 SQL을 실행하지 않았습니다. 보관본의 발견 사항이 이미 추출된 마트에 실제로 어느 정도 영향을 주었는지는 확인되지 않았습니다.
